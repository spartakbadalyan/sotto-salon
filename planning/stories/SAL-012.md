# SAL-012: Implement privacy-preserving visitor age access

Epic: EPIC-03. Tracking: `planning/roadmap.yaml`.

## Outcome

Apply reviewed age rules without creating visitor identity profiles.

## Scope

Implement privacy-preserving visitor age access. Follow `docs/product/mvp.md` and the roadmap dependencies. No service payments, commissions or booking functionality.

## Requirements

- Use approved threshold/proof by territory/content, not a checkbox.
- Bind short-lived assertions to audience/session; gate pages, APIs, search, contact and media server-side.
- Offer accessible fallback and neutral pre-gate/help pages; no tracking profiles.

## Data and API

Minimal AgeAssertion: threshold, issuer/audience, expiry and bounded anti-replay data, separate from advertiser identity.

## Failure and Security

Unverifiable proof/provider outage denies restricted content while reporting/help remain available.

## Acceptance Criteria

- SAL-012-AC01: Deep links, API and direct media cannot bypass required checks.
- SAL-012-AC02: Expired, replayed and wrong-audience proofs fail.
- SAL-012-AC03: Only necessary age outcome is retained for approved lifetime.
- SAL-012-AC04: Anonymous reporting/help work during age-provider outage.
